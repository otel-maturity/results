# Istio — Installation Plan

## Project Overview

Istio is a service mesh that injects Envoy proxy sidecars into application pods to provide traffic management, mTLS, and rich telemetry. All telemetry is generated by the Envoy data plane — no application code changes are required.

## Version

| Component | Version |
|-----------|---------|
| Istio (base, istiod, gateway) | **1.29.2** |
| Helm repo | `https://istio-release.storage.googleapis.com/charts` |

## Installation Method

Three Helm charts installed in order into the `istio-system` namespace:

1. **`istio/base`** — CRDs (Telemetry, VirtualService, Gateway, DestinationRule, etc.) and cluster-scoped resources
2. **`istio/istiod`** — Control plane (Pilot + Citadel + Galley merged). Configured with OTel extension providers for traces and access logs.
3. **`istio/gateway`** — Ingress gateway (Envoy) for routing external traffic into the mesh

## Telemetry Configuration

### Traces (OTLP gRPC)
Configured via `meshConfig.extensionProviders` in istiod Helm values:

```yaml
meshConfig:
  extensionProviders:
    - name: otel-tracing
      opentelemetry:
        port: 4317
        service: otel-collector-opentelemetry-collector.opentelemetry.svc.cluster.local
```

Activated by a mesh-wide `Telemetry` CR applied to `istio-system`:

```yaml
spec:
  tracing:
    - providers:
        - name: otel-tracing
      randomSamplingPercentage: 100   # 100% for evaluation
```

Envoy sidecars send spans to the OTel collector via OTLP gRPC on port 4317. W3C Trace Context (`traceparent`) is propagated automatically.

### Access Logs (OTLP gRPC via ALS)
Also configured via `extensionProviders`:

```yaml
meshConfig:
  extensionProviders:
    - name: otel-als
      envoyOtelAls:
        port: 4317
        service: otel-collector-opentelemetry-collector.opentelemetry.svc.cluster.local
```

Activated in the same `Telemetry` CR:

```yaml
spec:
  accessLogging:
    - providers:
        - name: otel-als
```

Envoy streams access log entries as OTLP LogRecords to the collector.

### Metrics (Prometheus scrape)
Istio does **not** support OTLP metrics export. Metrics are exposed as Prometheus endpoints:

| Source | Port | Path |
|--------|------|------|
| istiod control plane | 15014 | `/metrics` |
| Envoy sidecar (per pod) | 15090 | `/stats/prometheus` |
| Ingress gateway | 15020 | `/stats/prometheus` |

## Collector Changes

The OTel collector's `values.yaml` is updated to add a `prometheus` receiver with three scrape jobs:

1. `istio-istiod` — scrapes the istiod service endpoint on port 15014
2. `istio-ingressgateway` — scrapes gateway pods on port 15020
3. `istio-envoy-sidecars` — scrapes all sidecar-injected pods on port 15090

The `prometheus` receiver is added to the `metrics` pipeline alongside `k8s_cluster`.

## Routing / Ingress Setup

Traffic is routed through the Istio Ingress Gateway to the `otel-eval-backend` service in the `demo` namespace:

```
curl → NodePort 30080 → Istio Ingress Gateway (istio-system) → otel-eval-backend (demo)
```

Resources:
- **Gateway** (`istio-system/eval-gateway`) — listens on port 80, accepts all hosts
- **VirtualService** (`demo/eval-backend`) — routes all traffic to `otel-eval-backend:3000`

The `demo` namespace is labeled `istio-injection: enabled` so the test backend pod gets an Envoy sidecar, generating spans for inbound requests.

## Sidecar Injection

The `demo` namespace must be labeled for automatic sidecar injection. The backend pod will be restarted after labeling to get the sidecar injected.

```bash
kubectl label namespace demo istio-injection=enabled --overwrite
kubectl rollout restart deployment/otel-eval-backend -n demo
```

## Traffic Generation

```bash
# Port-forward to the ingress gateway NodePort (or use docker exec)
# Send 20 requests through the gateway

# Without trace context (Istio starts new traces)
for i in $(seq 1 10); do
  curl -s http://localhost:30080/ | jq .
done

# With W3C Trace Context (Istio propagates existing trace)
for i in $(seq 1 10); do
  curl -s -H "traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01" \
    http://localhost:30080/ | jq .
done
```

## Step-by-Step Installation

```bash
# 1. Create namespace
kubectl create namespace istio-system --dry-run=client -o yaml | kubectl apply -f -

# 2. Install CRDs (base chart)
helm upgrade --install istio-base istio/base \
  --namespace istio-system \
  --version 1.29.2 \
  --wait

# 3. Install control plane (istiod)
helm upgrade --install istiod istio/istiod \
  --namespace istio-system \
  --version 1.29.2 \
  -f .otel-eval/istio/istio/istiod-values.yaml \
  --wait --timeout 5m

# 4. Install ingress gateway
helm upgrade --install istio-gateway istio/gateway \
  --namespace istio-system \
  --version 1.29.2 \
  -f .otel-eval/istio/istio/gateway-values.yaml \
  --wait --timeout 3m

# 5. Apply Telemetry CR (mesh-wide tracing + access logging)
kubectl apply -f .otel-eval/istio/istio/telemetry.yaml

# 6. Label demo namespace for sidecar injection
kubectl label namespace demo istio-injection=enabled --overwrite
kubectl rollout restart deployment/otel-eval-backend -n demo
kubectl rollout status deployment/otel-eval-backend -n demo --timeout=2m

# 7. Apply routing resources
kubectl apply -f .otel-eval/istio/istio/routing/gateway-vs.yaml

# 8. Upgrade OTel collector with Prometheus scrape configs
helm upgrade otel-collector open-telemetry/opentelemetry-collector \
  --namespace opentelemetry \
  -f .otel-eval/istio/collector/values.yaml \
  --wait

# 9. Generate traffic and verify telemetry
```
